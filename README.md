# Проект «Школьный штаб»

Асинхронный MAX-бот с кабинетами ученика, учителя, психолога и родителя. Данные хранятся в PostgreSQL; заявки сотрудников подтверждаются в защищенной веб-админке.

## Стек технологий

- **Python 3.12+** — рекомендуемая версия для локальной разработки и запуска.
- **maxapi** — асинхронный бот MAX, работающий через long polling.
- **SQLAlchemy 2.x** с `AsyncSession` и **asyncpg** — асинхронная работа с PostgreSQL.
- **PostgreSQL 15** — основная база данных; в Docker Compose используется образ `postgres:15-alpine`.
- **Alembic** — миграции схемы БД.
- **FastAPI**, **Uvicorn** и **Jinja2** — веб-админка для рассмотрения заявок сотрудников.
- **python-dotenv** — загрузка конфигурации из `.env`.
- **cryptography (Fernet)** — обратимое шифрование паролей классов; для проверки входа отдельно хранится PBKDF2-хэш.
- **Docker Compose** — локальный запуск PostgreSQL, миграций, бота и админки.

Зависимости проекта перечислены в [requirements.txt](./requirements.txt), контейнерная конфигурация — в [Dockerfile](./Dockerfile) и [docker-compose.yml](./docker-compose.yml).

Модули `app/handlers/` и `app/services/` содержат также существующие функции учебного MVP. При расширении проекта сохраняйте проверки роли и статуса для каждого нового действия.

## Подробный запуск через Docker Compose (Windows)

Это рекомендуемый способ: Docker запускает PostgreSQL, применяет миграции, а затем поднимает MAX-бота и веб-админку. Команды ниже выполняйте в **PowerShell из корневой папки проекта** — там, где лежит `docker-compose.yml`.

### 1. Подготовьте инструменты и проект

1. Установите Docker Desktop для Windows и запустите его. Дождитесь состояния, в котором Docker Engine работает.
2. Откройте PowerShell и перейдите в папку проекта (если PowerShell уже открыт в ней, переход не нужен):

   ```powershell
   Set-Location C:\asdsad
   ```

   Если проект лежит в другой папке, укажите ее вместо `C:\asdsad`.
3. Убедитесь, что в папке есть Compose-файл и Docker доступен:

   ```powershell
   Get-Item .\docker-compose.yml
   docker --version
   docker compose version
   ```

   Если команда Docker не работает, сначала запустите Docker Desktop. Если `docker compose` не распознается, обновите Docker Desktop до версии с Compose V2.

### 2. Создайте и заполните `.env`

Создайте локальный файл настроек из шаблона:

```powershell
Copy-Item .env.example .env
notepad .env
```

В `.env` замените значения-заглушки:

- `BOT_TOKEN` — токен вашего MAX-бота.
- `POSTGRES_PASSWORD` — придумайте отдельный пароль для PostgreSQL.
- `ADMIN_USERNAME` и `ADMIN_PASSWORD` — учетные данные для веб-админки; обязательно замените демонстрационный пароль.
- `CLASS_PASSWORD_KEY` — Fernet-ключ для шифрования паролей классов. Создайте его командой:

  ```powershell
  docker run --rm python:3.12-slim python -c "import base64, secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"
  ```

  Скопируйте выведенную строку целиком после `CLASS_PASSWORD_KEY=`. Команда скачает образ Python при первом использовании.

В шаблоне уже заданы `POSTGRES_USER`, `POSTGRES_DB` и `DATABASE_URL`. Для Docker адрес БД в `DATABASE_URL` должен иметь хост `db` — это имя сервиса PostgreSQL внутри Compose-сети, не `localhost`. Если вы изменяете имя пользователя, пароль или БД, согласованно обновите `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` и данные подключения в `DATABASE_URL`. Чтобы избежать ошибок URL-кодирования, для пароля БД используйте латинские буквы и цифры.

Не добавляйте `.env` в Git и не отправляйте его в чаты. Сохраните `CLASS_PASSWORD_KEY` в надежном месте: без прежнего ключа сохраненные пароли классов нельзя расшифровать и показать учителям. Не меняйте этот ключ после начала работы с классами.

### 3. Соберите и запустите сервисы

Из корня проекта выполните:

```powershell
docker compose up --build -d
```

При первом запуске Docker скачает базовый образ и зависимости Python, поэтому запуск может занять несколько минут. Compose выполнит шаги в нужном порядке:

1. запустит PostgreSQL;
2. дождется готовности БД;
3. выполнит `alembic upgrade head` в одноразовом сервисе `migrate`;
4. запустит бота и веб-админку.

### 4. Убедитесь, что все запустилось

Посмотрите состояние контейнеров, включая завершившийся сервис миграций:

```powershell
docker compose ps -a
```

Сервис `migrate` после успешного применения схемы может отображаться как завершенный с кодом `0` — это нормально. Посмотрите его лог:

```powershell
docker compose logs migrate
```

В конце лога миграций не должно быть traceback или ошибки подключения. Проверьте логи бота и админки:

```powershell
docker compose logs --tail 100 bot
docker compose logs --tail 100 admin
```

Чтобы следить за логами бота в реальном времени:

```powershell
docker compose logs -f bot
```

Выход из просмотра логов по `Ctrl+C` **не останавливает контейнер**.

### 5. Проверьте бота и админку

- Откройте в браузере <http://localhost:8000/admin/requests>. Браузер запросит HTTP Basic Auth: введите `ADMIN_USERNAME` и `ADMIN_PASSWORD` из `.env`. Для поиска, фильтрации, смены роли и удаления зарегистрированных пользователей откройте <http://localhost:8000/admin/accounts>.
- Найдите бота в MAX и отправьте `/start`. Пройдите регистрацию тестовым аккаунтом.
- Заявки пользователей с ролями «Учитель» и «Психолог» появятся в админке. Одобрите заявку там, затем откройте боту `/start` повторно.
- Учитель может создать класс; ученик может присоединиться по логину и паролю; запрос родителя должен подтвердить ученик.

### Повторный запуск, остановка и сохранение данных

После перезагрузки компьютера запустите Docker Desktop, затем из папки проекта выполните:

```powershell
docker compose up -d
```

Чтобы остановить контейнеры, не удаляя данные БД:

```powershell
docker compose down
```

Пользователи и классы хранятся в Docker volume `pgdata`, поэтому команда `down` их не удаляет. **Не выполняйте `docker compose down -v`, если не хотите удалить базу и все данные.** При изменении кода или зависимостей пересоберите и перезапустите контейнеры:

```powershell
docker compose up --build -d
```

### Типовые проблемы

- **`BOT_TOKEN` не задан / бот не запускается:** проверьте токен в `.env`, затем пересоздайте контейнеры командой `docker compose up -d --force-recreate bot`.
- **Миграции завершились с ошибкой:** проверьте лог `docker compose logs migrate`, доступность сервиса БД и соответствие `DATABASE_URL` значениям `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`.
- **Админка не открывается:** проверьте `docker compose ps -a` и `docker compose logs --tail 100 admin`. Убедитесь, что порт `8000` не занят другим приложением.
- **PostgreSQL не запускается или порт занят:** проверьте `docker compose logs --tail 100 db`. Если на компьютере уже работает PostgreSQL на порту `5432`, освободите порт или измените левую часть публикации порта `"5432:5432"` в Compose-файле.
- **Изменили `.env`, но сервис использует старые настройки:** пересоздайте сервисы командой `docker compose up -d --force-recreate`.
- **Потеряли `CLASS_PASSWORD_KEY`:** не генерируйте новый ключ с тем же именем в надежде восстановить данные — он не расшифрует старые пароли классов. Восстановите сохраненную копию исходного ключа.

## Локальный запуск

Понадобятся Python 3.12 или новее, PostgreSQL и заполненный `.env`. Для локального запуска укажите в `DATABASE_URL` адрес базы `localhost`, например:

```text
postgresql+asyncpg://hq_user:ваш_пароль@localhost:5432/school_hq_db
```

Если `CLASS_PASSWORD_KEY` еще не задан, сгенерируйте его через стандартную библиотеку Python и сохраните в `.env`:

```powershell
py -3 -c "import base64, secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"
```

В PowerShell из корня проекта выполните:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
alembic upgrade head
python -m app.main
```

Бот работает через long polling; веб-админка доступна на порту 8000. Чтобы запустить ее локально в отдельном окне PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
uvicorn app.admin_web.main:app --host 127.0.0.1 --port 8000
```

Если PowerShell запрещает активацию виртуального окружения, выполните `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`, затем повторите активацию.

## Реализованные сценарии

- Новые пользователи регистрируются с ФИО и выбирают постоянную роль. Если у заявки учителя/психолога ФИО не сохранилось, бот повторно запросит его при `/start`. Ученики и родители получают доступ сразу; учителя и психологи — только после одобрения в админке.
- Одобренный учитель создает класс с уникальным логином и паролем; ученик вступает в него по этим данным.
- Родитель находит ученика по точному ФИО или уникальному MAX ID. Связь становится активной только после подтверждения учеником в боте; у родителя поддерживается несколько подтвержденных связей.
- Пароль класса хранится в виде PBKDF2-хэша для проверки входа и шифротекста Fernet для показа в списке учителя. Пароль шифруется ключом `CLASS_PASSWORD_KEY`; потеря или замена ключа лишит возможности его расшифровать.
- Миграции схемы выполняются Alembic (`alembic upgrade head`). Админка использует HTTP Basic Auth; задайте непустые учетные данные до ее публикации. Для внешнего доступа дополнительно настройте HTTPS и ограничение доступа на уровне прокси/сети.
- Админка `/admin/accounts` позволяет искать пользователей по ФИО, школе и MAX ID, фильтровать по роли/статусу, менять роль и удалять аккаунт. Назначение роли учителя/психолога администратором сразу одобряет доступ. При удалении аккаунта каскадно удаляются его классы, связи и принадлежащие ему данные; при смене роли удаляются несовместимые членства, связи родителя/ученика и классы учителя.

## Продолжение разработки и восстановление контекста

Этот раздел фиксирует текущее состояние реализации, чтобы к работе можно было вернуться независимо от истории чата.

### Что уже сделано и где искать

- **Хранение данных:** модели пользователей, классов, участников классов, родительских связей и существующих функций MVP описаны в `app/db/models.py`; подключение к БД — в `app/db/database.py`; CRUD-сценарии и обработка паролей классов — в `app/db/crud.py`.
- **Роли и регистрация:** `/start`, первоначальный выбор роли, запрос ФИО сотрудника при необходимости, проверка статуса и маршрутизация кабинетов реализованы в `app/main.py`. Роль после регистрации не должна меняться; новые сотрудники ожидают одобрения.
- **Классы:** учитель создает класс, ученик присоединяется по логину и паролю. Пароль проверяется по хэшу, а его шифротекст позволяет показать пароль учителю повторно.
- **Родитель и ученик:** запрос создается по ФИО или MAX ID; подтверждение/отклонение выполняет сам ученик в MAX. Логика БД — в `app/db/crud.py`, обработка MAX — в `app/main.py`.
- **Админка:** FastAPI-страница и обработчики заявок находятся в `app/admin_web/main.py`, шаблон — в `app/admin_web/templates/admin.html`.
- **Схема БД:** конфигурация миграций — в `alembic.ini` и `migrations/env.py`; начальная ревизия — `migrations/versions/0001_initial.py`, адаптация ранее созданных таблиц MVP — `migrations/versions/0002_adapt_legacy_schema.py`, значение по умолчанию для времени регистрации — `migrations/versions/0003_users_created_at_default.py`.
- **Запуск и секреты:** Docker Compose описан в `docker-compose.yml`; переменные окружения — в `.env.example`; инструкция установки и запуска находится выше в этом README.
- **Проверки:** основные тесты находятся в `tests/test_rbac.py`.

### Проверки и известные ограничения

На момент последней проверки прошли `23` теста (`python -m pytest -q tests`), компиляция модулей Python, проверка `git diff --check` и генерация SQL миграции Alembic в offline-режиме. Полноценный запуск контейнеров с реальным PostgreSQL и MAX API в этой среде не выполнялся; после настройки `.env` проверьте запуск по инструкции выше.

FSM-состояния диалога бота хранятся в памяти процесса и сбрасываются при перезапуске бота. Для производственного сценария с переживанием перезапусков потребуется отдельное постоянное хранилище состояний.

### Что сохранить, чтобы продолжить работу

1. Сохраните изменения проекта в Git или в резервной копии. Перед началом следующей сессии проверьте `git status` и не удаляйте незакоммиченные изменения.
2. Храните `.env` отдельно и безопасно: файл содержит токен MAX, пароли и `CLASS_PASSWORD_KEY`; его нельзя публиковать или добавлять в Git.
3. Сделайте резервную копию PostgreSQL. При Docker-запуске данные лежат в volume `pgdata`; команда `docker compose down -v` удаляет этот volume вместе с базой.
4. Сохраните `CLASS_PASSWORD_KEY` отдельно от базы. Без исходного ключа нельзя расшифровать сохраненные пароли классов; заменять его без процедуры повторного шифрования нельзя.
5. Для быстрого восстановления контекста начните с этого README, затем просмотрите `git status`, `app/main.py`, `app/db/`, `app/admin_web/` и `migrations/versions/0001_initial.py`. Проверьте тесты командой `python -m pytest -q tests`.

Следующие полезные шаги: запустить приложение с реальными настройками MAX и PostgreSQL, проверить полный пользовательский сценарий в тестовом чате, а затем при дальнейших изменениях схемы создавать отдельные Alembic-ревизии.
